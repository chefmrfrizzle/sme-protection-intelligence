# Implementation Plan

## P0 - recording-ready demonstration

1. Typed protection states, provenance, temporal facts, events, policies, rule traces, findings, challenges, assessment versions, reviews, and audit events.
2. Complete synthetic Pacific Components Pte Ltd corpus with policy, schedules, cyber summary, wording, endorsements, lease, assets, suppliers, financials, and infrastructure.
3. Deterministic event reducer, completeness evaluator, materiality engine, reconciliation rules, challenge pass, alignment calculation, and receipt hashing.
4. Overview, changes timeline, protection, evidence, finding detail, reports, audit, simulator, responsive shell, reset, replay/live-mode labels, and role-aware language.
5. Server-generated professional PDF and assessment receipt.
6. Unit, schema, golden-rule, challenge, report, and Playwright reset-to-report coverage.
7. Vercel production deployment and a sanitized public GitHub repository.

## P1 - after the deterministic demo remains stable

- completed: tenant-scoped repositories, validated review endpoints, Supabase
  passwordless authentication, database-backed assessment/review/audit/report
  receipts, RLS, and a private evidence bucket;
- next: approved member invitation and authenticated role-specific views;
- next: signed evidence upload/download routes using the private bucket;
- live bounded extraction adapter and evaluation telemetry;
- comparison reports and richer graph audit view;
- signed API event ingestion with idempotency.

## P2 - production programme

- read-only accounting, ERP, cloud, supplier and broker connectors;
- renewal workflow and multi-policy programmes;
- operational queues, observability, disaster recovery, retention, DSR/deletion, and vendor governance;
- security, privacy, model-risk, legal and Singapore regulatory review;
- load, penetration, tenancy, recovery, and human-factors testing.

## Acceptance path

From a reset state: understand baseline -> apply warehouse change -> inspect candidate and source excerpts -> inspect challenge result -> apply cloud change -> observe abstention -> request review -> generate report -> inspect versioned audit history.
